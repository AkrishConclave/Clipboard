## 2024-11-25 - [Clipboard Data Truncation]
**Vulnerability:** The clipboard manager was reading unrestricted string data from the clipboard and storing it in memory and attempting to serialize it to JSON, opening up potential memory exhaustion (DoS) attacks or app crashes if extremely large strings were copied to the clipboard.
**Learning:** In any application handling arbitrary clipboard data, there is a risk of processing massive amounts of data unintentionally (either maliciously or accidentally copied by a user). This is a hidden DoS vector.
**Prevention:** Always implement a reasonable maximum length threshold (e.g., 5,000,000 characters or ~5MB) when capturing and storing clipboard string data. Truncate inputs that exceed this length. Setting this threshold too low (e.g., 10,000 characters) will lead to functional regressions where users lose data for larger legitimately copied items like source code or logs.
## 2024-11-25 - [Data Leakage on Logout]
**Vulnerability:** The application was keeping sensitive clipboard history in memory even after a user logged out, due to the use of global/app-level state (@StateObject on the App struct). The next logged-in user could see the previous user's clipboard history.
**Learning:** When using global or app-level state management in SwiftUI, sensitive data is not automatically cleared when user sessions end or views are destroyed. This can lead to severe data leakage between sessions on the same device.
**Prevention:** Always explicitly clear sensitive in-memory state during the logout process or session termination. Ensure methods like `clearData()` exist on state managers and are called during the un-authentication flow.
## 2024-11-25 - [Network Resource Exhaustion and Data Leakage]
**Vulnerability:** The application was making background network requests to a third-party synchronization server without a defined timeout, creating a local Denial of Service (DoS) risk from hanging sockets. Additionally, it was logging verbose, localized system networking errors (`error.localizedDescription`), which can unintentionally leak sensitive data like internal proxy configurations, file paths, or network topologies into application logs.
**Learning:** Background synchronization systems that lack timeouts can silently exhaust application network resources if the remote server becomes unresponsive. Furthermore, relying on default system error messages in network handlers can violate data minimization principles and leak operational intelligence.
**Prevention:** Always enforce explicit `timeoutInterval` constraints on `URLRequest` instances (e.g., 10 seconds). For error logging, replace verbose system descriptions with generic, static strings (e.g., "Network request failed") in production builds, saving detailed contexts for secure, authenticated audit logs if strictly necessary.
## 2024-11-25 - [Auto-Generated Password Leakage]
**Vulnerability:** The clipboard manager checked for `org.nspasteboard.ConcealedType` and other known password types, but omitted `org.nspasteboard.AutoGeneratedType`. Auto-generated passwords from modern password managers would bypass the filter and get logged and synced with a server, potentially exposing them to unauthorized users.
**Learning:** Certain secure macOS APIs mark auto-generated passwords specifically. Omitting this type leaves a severe vulnerability for users utilizing native tools.
**Prevention:** Always filter out `org.nspasteboard.AutoGeneratedType` in native macOS applications handling clipboard information, in addition to standard obscured types.
## 2024-11-25 - [Unauthenticated Background Data Exfiltration]
**Vulnerability:** The clipboard manager's background timer would continuously monitor the pasteboard, extract data, and sync it to the remote server even if the user had logged out but the app remained running.
**Learning:** Background timers and background sync processes often run completely detached from the UI authentication state. This can lead to silent exfiltration of sensitive data the user assumes is private since they are "logged out".
**Prevention:** Always add explicit authentication state checks (e.g., `UserDefaults.standard.bool(forKey: "isLoggedIn")`) at the very beginning of background tasks that access sensitive system resources like the pasteboard or microphone.
